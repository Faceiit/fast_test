# Архитектура проекта

## Общее описание

Secret Management Service — это контейнеризированный сервис для безопасного хранения и выдачи секретов.

Под секретами понимаются:

- пароли от баз данных;
- API-ключи;
- токены;
- другие чувствительные данные, которые не должны храниться в коде или конфигурационных файлах приложений.

Система состоит из трех основных компонентов:

- Nginx;
- FastAPI backend;
- PostgreSQL.

## Компоненты системы

### Nginx

Nginx является единой внешней точкой входа в систему.

Он принимает HTTP-запросы от клиентов и передает их во внутренний FastAPI-сервис.

Основные задачи Nginx:

- принимать внешние запросы;
- передавать запросы в FastAPI;
- скрывать FastAPI от прямого доступа снаружи;
- добавлять базовые security headers;
- ограничивать слишком частые запросы;
- вести access logs.

Nginx не занимается проверкой прав доступа к секретам и не работает с базой данных.

### FastAPI

FastAPI содержит основную бизнес-логику проекта.

Основные задачи FastAPI:

- аутентифицировать пользователей и service accounts;
- проверять права доступа;
- шифровать секреты перед сохранением;
- расшифровывать секреты перед выдачей;
- работать с PostgreSQL;
- записывать audit events.

FastAPI является главным компонентом системы, который решает, можно ли конкретному пользователю или приложению получить конкретный секрет.

### PostgreSQL

PostgreSQL используется для хранения данных приложения.

В базе данных хранятся:

- пользователи;
- service accounts;
- роли;
- права доступа;
- метаданные секретов;
- зашифрованные версии секретов;
- audit logs.

PostgreSQL не должен хранить:

- секреты в открытом виде;
- пользовательские пароли в открытом виде;
- API-ключи в открытом виде;
- master key для шифрования секретов.

## Общая схема работы

```text
Клиент
  |
  v
Nginx
  |
  v
FastAPI
  |
  v
PostgreSQL
```

## Пример чтения секрета

1. Клиент отправляет запрос в Nginx.
2. Nginx передает запрос в FastAPI.
3. FastAPI проверяет, кто сделал запрос.
4. FastAPI проверяет, есть ли доступ к нужному секрету.
5. FastAPI получает зашифрованный секрет из PostgreSQL.
6. FastAPI расшифровывает секрет в памяти приложения.
7. FastAPI записывает событие в audit log.
8. FastAPI возвращает секрет клиенту.

## Основные правила безопасности

* Секреты не хранятся в базе данных в открытом виде.
* Секреты не записываются в логи.
* Пароли пользователей хранятся только в виде хэшей.
* API-ключи service accounts хранятся только в виде хэшей.
* Master key не хранится в PostgreSQL.
* PostgreSQL не доступен напрямую снаружи.
* Доступ к каждому секрету проверяется отдельно.
